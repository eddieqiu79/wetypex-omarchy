# WeTypeX Omarchy 0.1.0-rc.4

Preview candidate for Arch / Omarchy x86_64. This update fixes file invitations initiated by a paired Mac or phone and redesigns the native transfer window around choosing files, choosing a device and sending. It does not change clipboard copy/paste or add background file reception while the transfer window is closed.

## Native transfer interface

- Separate send and receive views, associated-device cards, readable file sizes and a single primary send action. Narrow windows stack the file and device panels.
- Show incoming invitations in the receive view with explicit accept/reject buttons and the destination directory. Acceptance applies to the connection; the backend does not offer per-file receiving consent.
- Keep phone QR and manual receive connections under connection help. Association labels do not claim a device is online.
- Restore readable failed uploads to the pending list for explicit retry. Missing/unreadable files require reselection. Canceling a connection wait preserves unsent files; stopping active transfers requires confirmation.
- Preserve backend-driven progress and completion checks. Sending success remains a sender-side report; receiving is marked saved only after the local path/size check.

## Fixes

- Query incoming invitations and the paired-device list while the transfer window is idle. Validate the sender, ask before receiving, then join the existing transfer code instead of creating a new invitation.
- Load devices automatically and select the invitation sender. The previous window could remain on a disabled “refresh paired devices” placeholder during connection setup.
- End waiting on canceled or rejected peer states, restoring the idle controls.
- Match the advertised ACK capability in the direct Flurry server. The WXP2P branch already enabled it. Its independent contribution to the original failure was not isolated.
- Allow a preloaded backend to enter direct TLS without changing the already-published certificate; prevent a late dispatch from switching an established direct role.

The release also includes the main-branch activation-path and build-time Qt dependency fixes made after the rc.3 tag. Unrelated local settings-window changes are excluded.

## Evidence

On 2026-11-01 the maintenance user confirmed successful file transfers from Mac to Linux and from phone to Linux using the patched test build. File hashes, large-file stress, long-duration operation and the full outbound matrix were not revalidated. Official client versions were not recaptured for this round.

The transfer application and GUI tests compiled successfully after the interface redesign. The Qt test run passed all 18 reported checks, including setup/cleanup and synthetic screenshots; account-preflight and invitation-wrapper checks also passed. Wide and narrow send views and the incoming invitation view were inspected using synthetic data. Real-device transfer has not been repeated with the redesigned interface.

Before the redesign, the complete local source snapshot compiled successfully and the broader local run passed 9 of 11 suites; HEIF/AVIF decoding and the settings single-instance test were blocked by the execution sandbox's D-Bus/local-socket restrictions. The release preparation workflow must pass the full clean Arch build, tests and package transactions for the exact tagged commit before producing the release draft. Device testing and package CI are separate evidence.

See [the detailed fix record](../FILE-RECEIVE-FIX.zh-CN.md) for causes and verification limits. Installation and publication are not implied by these source/test results.

## Install and recovery

Use the exact tag `v0.1.0-rc.4` with the preview channel after publication, following [the release installation guide](../RELEASE-INSTALL.md). Keep the file-transfer window open to receive an invitation and accept it before connecting. This is still a preview, not a stable release.

Retain the previous compatible package for rollback. Existing pairing, runtime, dictionaries and preferences remain in place. Runtime `2.2.3.657` is obtained separately; the package contains no official engine, dictionaries, extracted UI, credentials or transferred user files. Existing license notices remain applicable.

The binary package requires at least its build-time Qt minor version, recorded in its dependencies. A host still using Qt 6.11 must not force-install a Qt 6.12 build. Build a local package from the verified release source/recipe against the installed dependency set and run all checks, or use the host's separately approved full-system update route.
