# WeTypeX Omarchy 0.1.0-rc.2

Second native-desktop release candidate. **Preview, not stable.** This version supersedes `0.1.0-rc.1` for testing the native GUI and phone file transfers. Published `rc.1` assets remain unchanged.

## Fixes since rc.1

- Phone handshakes no longer consume a dispatch before the peer certificate is available and saved. The same invitation can recover when credentials arrive later or a local save initially fails.
- Phone status distinguishes waiting for credentials, malformed base64, and a local file-write failure. Certificate files receive owner-only permissions before commit. Credential contents are not displayed or logged.
- Account operations check local engine dependencies before touching account state. A local runtime startup failure is distinguished from an unconfirmed server response; GUI request deadlines allow the bounded identity-lock wait and account operation.
- Arch package checks now run the installed account tool's read-only `network-info` probe to cover dynamically loaded runtime dependencies.

The isolated test deployment initially omitted libc++/libc++abi support libraries. Correcting its staging layout restored device discovery; the Arch recipe already declares libc++. This is not evidence that the public `rc.1` package had the same staging defect.

## Installation and updates

Use `v0.1.0-rc.2` with `--channel preview` as documented in [the release installation guide](../RELEASE-INSTALL.md). The stable channel continues to exclude candidates. Downloads verify immutable release and asset attestations, hashes and package metadata before explicit installation. No system package was installed on the maintenance desktop for this release.

Target: Arch/Omarchy x86_64. Official runtime remains pinned independently to `2.2.3.657`; original WeTypeX source baseline remains `291193a26938e0e8858d72b737066f37eb7a5f94`. No new proprietary runtime, account identity, dictionary, extracted UI or user test material is distributed. Component-specific MIT/GPL and dependency notices are retained. No user-state schema migration is introduced.

## Remaining acceptance and limitations

Exact package desktop input/settings and migration, restart, sleep/network recovery, and long-duration use remain required before stable publication. Package install/upgrade/rollback tests in clean Arch do not establish those desktop results.

Direct cross-device `.md`/`.pdf` file copy/paste, directory sending and per-file backend cancellation remain unsupported. File receiving consent applies to the connected session. Local received-file existence/size checks are not cross-device byte-integrity verification. Official service and runtime behavior can change.

Keep a compatible prior package for recovery. Explicit downgrade requires an exact old tag, `--allow-downgrade`, `--confirm` and a new download directory. A package downgrade is not a whole-system or account-state rollback. Private-prefix installations still require reviewed migration before system installation; finish active work before an authorized restart.
