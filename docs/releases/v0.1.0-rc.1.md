# WeTypeX Omarchy 0.1.0-rc.1

First installable release candidate for the native desktop GUI and verified Arch distribution channel. **Preview, not stable.** Real-device acceptance of this GUI build is still required before a stable release.

## Changes

- Real settings and file-transfer applications now use resizable native windows and the dark Omarchy-oriented interface; the standalone demo is not installed.
- Settings preserve existing backend mappings. Phrase operations and microphone discovery no longer block initial window construction; invalid config is not overwritten.
- File selection precedes sending, outgoing files are serialized, per-file results distinguish backend completion from locally checked received files, and the receive directory is visible.
- Session-wide receive consent, disconnect/close confirmation, stale-callback rejection, connection/no-progress timeouts, and single-instance window activation.
- Verified package download/install helper with stable/preview channels, explicit installation, immutable release/asset verification, package metadata checks and downgrade refusal by default.
- No automatic runtime acquisition, account migration, clipboard service activation or Fcitx restart.

## Compatibility and licensing

Target: Arch/Omarchy x86_64, Qt6, system libcurl. Official runtime remains pinned to `2.2.3.657` and is obtained separately under its applicable terms. No proprietary engine, dictionary, UI resource, account or user test material is bundled. Component-specific MIT/GPL and dependency notices remain included.

Original WeTypeX source baseline: `291193a26938e0e8858d72b737066f37eb7a5f94`. This release does not claim to include every later upstream commit. The upstream watcher reports drift for review.

## Installation and updates

Use the exact tag `v0.1.0-rc.1` with `--channel preview`, following [the release install guide](../RELEASE-INSTALL.md). Stable checks intentionally exclude this candidate. Published assets are immutable and are verified with GitHub release attestations before installation.

Existing private-prefix deployments require reviewed migration before a system package can be installed. Keep a fallback input method. The package does not alter user state or activate sync. Finish active typing/transfers before updating; explicitly restart affected processes only after authorizing the installation/restart scope.

## Evidence and limitations

Local full adapter build and nine CTest suites passed, including actual GUI construction and synthetic backend tests. The release workflow builds the exact tagged source in clean Arch and checks package installation, upgrade from the retained `61686a0` development baseline, rollback/re-upgrade, removal and synthetic user-state preservation. Consult the linked Actions run and the release source manifest for exact build provenance. A container transaction is not a live desktop upgrade.

Historical builds successfully exchanged text, PNG/JPEG images and ordinary files with official Mac 3.0.0 (670) and iPhone 3.5.5 clients. This candidate has not yet repeated that full device matrix. Long-running/sleep/network/load and multi-display/scaling behavior remain acceptance work.

Receiving consent is for the connected session, not individual incoming files. Directory send, per-file backend cancellation, and direct cross-device file clipboard copy/paste are not provided in this GUI. Received-file checks establish local existence and size, not sender/receiver byte equality. The original protocol/runtime remains subject to upstream service changes.

## Recovery

Keep the old compatible package. `wetypex-omarchy-package install --tag OLD_TAG --channel preview --allow-downgrade --confirm --directory NEW_DIRECTORY` verifies an older published package before an explicit pacman downgrade. For the pre-release development baseline, retain its CI package and manifest and use the exact package path with pacman. There is no automatic state downgrade or whole-system rollback. No state schema migration is introduced in this candidate.
